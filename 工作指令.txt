## Kimi Code 执行提示词

**任务：重构新建项目输入 + 创意扩散步骤独立输入 + 修复生成后错误跳转**

---

### Phase 1: 新建项目页面 — 输入内容改为"标题"

**改动范围**：`app/project/new/page.tsx`（或对应新建项目路由）

**具体修改**：
1. 页面主标题从"输入一段灵感，AI 将帮你扩散为完整的影视创意"改为"输入项目标题，开始你的 AI 影视创作"。
2. 输入框 `placeholder` 从灵感示例（如"赛博朋克风格的剑客在雨夜霓虹中复仇..."）改为标题示例（如"雨夜回收站"、"记忆修复师"）。
3. 输入框右下角字数统计保持 `0 / 1000` 不变。
4. 底部提示文案从"系统将始终保留你的原始灵感，所有扩展都基于此锚点"改为"项目标题将作为创作锚点，后续所有内容基于此展开"。
5. 按钮文案从"开始创意扩散"改为"创建项目"。
6. **数据存储**：确认 `Project` 表是否有 `title` 字段。如果有，直接存入 `title`；如果没有，先执行 migration 添加 `title TEXT` 字段，然后将用户输入存入 `title`。同时，`Project` 表应保留一个 `idea` 或 `inspiration` 字段（用于后续创意扩散步骤填写），但新建时可为空或默认值。
7. **创建后跳转**：创建项目成功后，跳转到该项目的工作流页面（`/project/[id]/workflow`），并停留在"创意扩散"步骤。

---

### Phase 2: 创意扩散步骤 — 新增创意输入区域

**改动范围**：`app/(dashboard)/project/[id]/workflow/page.tsx` 中创意扩散步骤对应的子组件/渲染逻辑

**具体修改**：
1. 在创意扩散步骤卡片内，"原始灵感锚点"下方（或上方，根据布局美观判断），**新增一个输入区域**：
   - 标签："输入你的创意方向"
   - 占位符："描述你的故事核心、世界观或情绪基调，例如：一个被遗弃的机器人在雨夜城市中收集人类情感残影..."
   - 多行文本框，字数限制 1000 字
   - 这是一个**可编辑的输入框**，不是只读展示
2. **数据绑定**：
   - 用户输入的内容保存到 `Project` 表的 `idea` / `inspiration` / `creative_input` 字段（确认实际字段名）。
   - 点击"生成创意方向"时，将**这个输入框的内容**作为参数发送给后端 API，而不是发送项目标题。
3. **按钮状态**：输入框为空时，"生成创意方向"按钮 disabled；有内容后启用。

---

### Phase 3: 修复"生成创意方向"后错误跳转到框架搭建

**问题**：点击"生成创意方向"后，界面直接跳到框架搭建，而不是留在创意扩散展示结果。

**根因排查**：
1. 找到创意扩散步骤中"生成创意方向"按钮的 `onClick` 处理函数。
2. 检查该函数成功后的逻辑：
   - 是否调用了 `router.push()` 或 `setCurrentStep('framework')`？
   - 是否在后端 API 返回后，前端错误地更新了全局步骤状态？
3. 检查工作流进度条的步骤高亮逻辑，确认它是根据 `project.currentStep` 还是前端本地状态渲染。

**修复逻辑**：
1. **前端**：生成创意方向成功后，**只更新当前步骤的数据**（如将生成的创意方向列表存入 `project.ideaDirections` 或类似字段），**绝不修改 `currentStep` 或 `activeStep`**。
2. 生成完成后，创意扩散步骤的 UI 应切换为"展示模式"：
   - 显示生成的多个创意方向卡片/列表
   - 提供"选择此方向"或"重新生成"按钮
   - 用户**手动选择**某个方向后，再提供"进入框架搭建"的按钮，此时才推进到下一步。
3. **后端**：确认 `POST /api/idea/generate`（或对应 API）不会返回 `nextStep: 'framework'` 或类似误导前端的字段。如果有，删除该字段。
4. **数据库**：确认生成创意方向后，`Project` 表的 `currentStep` 字段不会被后端更新为 `framework`。它应保持为 `idea_diffusion` 或 `creative_diffusion`，直到用户手动确认进入下一步。

---

### Phase 4: 数据流与状态机梳理

**确保以下流程成立**：

```
新建项目
  ↓ 输入标题 → 创建项目 → 跳转工作流（创意扩散步骤）
创意扩散步骤
  ↓ 显示项目标题（只读锚点）
  ↓ 用户输入创意描述（可编辑）
  ↓ 点击"生成创意方向" → 调用 API → 返回创意方向列表
  ↓ 前端展示创意方向（留在本步骤）
  ↓ 用户选择方向 / 重新生成
  ↓ 用户点击"进入框架搭建" → 推进到框架搭建步骤
```

**状态字段建议**：
- `Project.title`：新建时填入
- `Project.ideaInput`：创意扩散步骤中用户输入的创意
- `Project.ideaDirections`：AI 生成的创意方向数组（JSONB）
- `Project.selectedDirection`：用户选定的方向索引/ID
- `Project.currentStep`：当前进行到的步骤（枚举值）

---

### Phase 5: 边界检查

1. **旧数据兼容**：如果已有项目的 `title` 字段为空，在仪表盘/项目列表中显示时，fallback 到 `idea` 字段或显示"未命名项目"。
2. **输入校验**：新建项目时标题不能为空；创意扩散时创意输入不能为空（至少 10 字）。
3. **URL 参数**：确认从新建项目跳转到工作流时，URL 正确携带项目 ID，不需要额外 query 参数来指定步骤。

---

**执行顺序**：Phase 1（新建项目）→ Phase 2（创意扩散输入）→ Phase 3（修复跳转）→ Phase 4（状态机梳理）→ Phase 5（边界检查）。

**先执行 Phase 1 + Phase 3，这两项是用户最直观的需求。Phase 2 在确认数据库字段后执行。**
