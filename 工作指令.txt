## Phase 1：Mock 标记在重新生图后不消失

问题描述：生图结果带有「Mock」角标，点击「重新生图」后，Mock 标记仍然存在，预期是重新生成时应立即清除所有 Mock 标记。

排查方向：
1. 定位「重新生图」按钮的点击事件处理函数，追踪其触发的 API 调用和状态更新链路
2. 检查重新生图时，前端是否先清除了该资源的 mock/placeholder 状态，还是直接等待后端返回新数据后才更新
3. 检查后端重新生成返回的数据结构中，是否仍然包含 `isMock` 或 `isPlaceholder` 标记
4. 检查前端状态管理（React state / Zustand / Context），确认重新生图时是否显式将对应资源的 mock 状态重置为 false，或从缓存中移除旧数据

修改方向：
- 重新生图的交互触发时，前端应立即将目标资源的 mock 标记置为 false（或移除占位样式），再发起请求
- 如果后端返回的数据仍带 mock 标记，检查后端生成逻辑是否错误地继承了旧资源的 mock 字段
- 确保 UI 的 mock 角标渲染条件是实时响应状态变化的，而非仅在首次加载时判断

---

## Phase 2：角色设计英文提示词缺失

问题描述：部分角色设计卡片中，英文提示词（English Prompt）区域空白，未显示内容。

排查方向：
1. 打开 Supabase Dashboard 或本地 db.json 备份，直接检查 `character` / `asset` 表中对应记录的 `englishPrompt` / `promptEn` / `prompt` 字段是否有值
2. 如果数据库中有值但前端不显示 → 前端渲染逻辑问题（字段名映射错误、条件渲染过早返回、或组件未传入该字段）
3. 如果数据库中无值 → 数据生成/迁移问题（提示词生成时英文部分未保存、或迁移脚本遗漏该字段）
4. 检查前端角色设计详情/列表组件的 Props 和类型定义，确认英文提示词字段是否被正确定义和传递

修改方向：
- 数据层缺失：在提示词生成/保存逻辑中，确保中英文提示词同时写入数据库
- 渲染层缺失：修正组件 Props 传递链，确保英文提示词字段正确映射到展示组件
- 如果英文提示词在部分角色上确实不存在，考虑在 UI 上显示「重新生成提示词」按钮作为兜底

---

## Phase 3：人物设计图出现多个人物形象

问题描述：单个人物设计图（角色肖像）中出现了多个人物形象，且面部不完整。预期是每张设计图只包含一个完整面部的人物。

排查方向：
1. 定位人物设计图的提示词生成逻辑（Prompt Engineering 层），检查当前生成的英文提示词中是否包含限制人物数量的关键词（如 single person, solo, one character, only one person）
2. 检查是否有负面提示词/排除词（negative prompt / exclude tags）机制，确认是否排除了 multiple people, group, crowd, extra figures 等概念
3. 检查提示词中是否包含容易产生多人物的描述（如 family, couple, standing together, reflection in mirror 等），这些描述在文生图模型中容易产出多人构图
4. 如果是即梦/海螺等特定模型，检查其 API 是否支持 negative prompt 或 exclude 参数，以及当前调用是否传入了这些参数

修改方向：
- 在人物设计提示词生成模板中，强制注入「单人肖像」约束：前缀或后缀固定添加 "full body portrait of a single person, solo, only one character, complete face clearly visible, centered composition"
- 添加负面提示词/排除参数："multiple people, group, crowd, extra limbs, cropped face, partial face, out of frame"
- 如果模型 API 不支持负面提示词，通过强化正面描述权重来压制多人出现概率
- 确保「完整面部」通过 "full face, front facing, clear facial features, uncropped head" 等描述约束

---

## Phase 4：图片左下角角标固定不变

问题描述：使用不同比例（如 16:9 / 1:1 / 9:16）和不同模型（如即梦 4.5 / 其他模型）生图后，图片左下角角标显示的内容固定不变，未反映实际生成参数。

排查方向：
1. 定位图片卡片组件左下角角标的渲染代码，检查其显示的值是硬编码字符串还是从资源元数据中动态读取
2. 检查资源数据结构（asset / image 表或对象），确认是否存储了 `aspectRatio`、`model`、`modelVersion` 等字段
3. 检查生图 API 调用后的数据处理逻辑，确认返回的模型和比例信息是否被正确提取并保存到资源对象中
4. 检查前端组件 Props，确认角标组件是否接收了正确的动态参数，还是写死了默认值

修改方向：
- 将硬编码角标改为动态读取资源对象的 `model` 和 `aspectRatio` 字段
- 如果后端存储时未记录实际使用的模型和比例，在生图 API 调用成功后，将请求参数中的 model 和 aspectRatio 回写到资源元数据中
- 角标显示格式建议：`{aspectRatio} | {model}`，如 `16:9 | 即梦4.5`
- 如果资源无元数据，至少保证角标与生成时的请求参数一致

---

## Phase 5：人物设计英文提示词不可展开编辑

问题描述：人物设计部分底部没有可展开的英文提示词编辑区域，期望能展开查看/编辑英文提示词，且修改后重新生成时按修改后的提示词执行。

排查方向：
1. 定位人物设计卡片/详情页的 UI 组件，检查当前是否已实现可折叠/展开的交互区域（如 Accordion / Collapse / Drawer）
2. 检查该组件当前是否仅渲染中文提示词，英文提示词是否被隐藏或未传入
3. 检查编辑后的提示词保存逻辑：修改后的英文提示词是否通过 API 回写到数据库，还是仅存在本地 state 中
4. 检查重新生图时的提示词读取链路：重新生成时是从数据库读取最新提示词，还是从缓存/旧对象中读取

修改方向：
- 在人物设计卡片底部添加可展开/折叠的「英文提示词」区域（默认收起，点击展开），使用标准 UI 组件（如 shadcn Collapsible 或自定义展开动画）
- 展开后显示英文提示词文本，并提供「编辑」按钮，进入可编辑状态（textarea 或 input）
- 编辑完成后提供「保存」按钮，调用 API 将修改后的英文提示词更新到数据库对应记录
- 重新生图时，确保生成逻辑读取的是数据库中最新的提示词（而非首次生成时的旧缓存），可在重新生成 API 中强制重新查询数据库获取最新 prompt
- 如果前端有本地缓存机制（SWR / React Query / Zustand），在保存成功后失效对应缓存或主动更新缓存
