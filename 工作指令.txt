这是执行代码里**完全没有调用** `logOperation` 的问题。之前建的表和工具函数只是基础设施，现在需要在每个工作流步骤的**执行成功回调**中显式插入写入逻辑。

---

## Kimi Code 执行提示词

**任务：在工作流全步骤执行成功后注入操作日志写入**

---

### Phase 1: 定位所有执行函数的注入点

在项目中全局搜索以下关键词，找到用户点击"开始执行"、"确认执行"、"生成创意方向"后**实际触发业务逻辑**的函数：

```
搜索关键词（按优先级）：
- "开始执行"
- "确认执行"  
- "生成创意方向"
- "重新生成"
- handleGenerate
- handleExecute
- onExecute
- onConfirm
- generateStyle / generateFramework / generateIdea 等
```

**注入位置**：在这些函数**成功返回结果后**（`try` 块末尾、`return` 之前），插入 `logOperation` 调用。

---

### Phase 2: 注入代码模板

**如果执行逻辑在 API Route（`app/api/.../route.ts`）中**：

```ts
import { logOperation } from '@/lib/operations';

// 在 POST handler 中，业务逻辑成功后
await logOperation({
  userId: user.id,           // 从 auth session 获取
  projectId: body.projectId,   // 从请求 body 获取
  stepName: 'style_unify',   // 见下方映射表
  actionType: 'generate',    // generate | regenerate | skip | confirm
  cost: 20,                  // 从 lib/points-config.ts 读取
  status: 'success',
});
```

**如果执行逻辑在 Server Action 中**：

```ts
'use server';
import { logOperation } from '@/lib/operations';

export async function generateFramework(projectId: string, ...) {
  // ... 业务逻辑 ...
  
  await logOperation({
    userId: session.user.id,
    projectId,
    stepName: 'framework',
    actionType: 'generate',
    cost: 10,
    status: 'success',
  });
  
  return result;
}
```

**如果执行逻辑在 Client Component 中直接 fetch 外部 API**（如直接调用即梦/海螺 API）：
- **方案 A（推荐）**：在后端新增一个 `/api/log-operation` 的 POST 路由，前端执行成功后先调用它。
- **方案 B**：将执行逻辑改为走 Server Action，在 Action 内部统一处理业务 + 日志。

---

### Phase 3: 各步骤 stepName 映射表（严格统一）

| 界面步骤 | stepName | 成本常量（从 points-config.ts 读取） |
|---------|----------|----------------------------------|
| 创意扩散 | `idea_diffusion` | `STEP_COSTS.idea` |
| 框架搭建 | `framework` | `STEP_COSTS.framework` |
| 风格统一 | `style_unify` | `STEP_COSTS.style` |
| 人物设计 | `character_design` | `STEP_COSTS.character` |
| 概念图 | `concept_art` | `STEP_COSTS.concept` |
| 宣传片 | `trailer` | `STEP_COSTS.trailer` |
| 分镜设计 | `storyboard` | `STEP_COSTS.storyboard` |
| 生成尾帧 | `ending_frame` | `STEP_COSTS.ending` |
| 直出视频 | `direct_video` | `STEP_COSTS.direct` |

**actionType 规则**：
- 用户点击"开始执行" / "生成创意方向" / "确认执行" → `'generate'`
- 用户点击"重新生成" → `'regenerate'`
- 用户点击"跳过" → `'skip'`

---

### Phase 4: 失败时也要记录

在每个执行函数的 `catch` 块中补充失败日志：

```ts
} catch (error) {
  await logOperation({
    userId: user.id,
    projectId,
    stepName: 'style_unify',
    actionType: 'generate',
    cost: 0,
    status: 'failed',
    metadata: { error: error instanceof Error ? error.message : String(error) },
  });
  throw error;
}
```

---

### Phase 5: 验证写入

1. 完成至少一个步骤的注入后，本地执行一次该步骤（如创意扩散或风格统一）。
2. 立即在 Supabase SQL Editor 执行：
   ```sql
   SELECT * FROM "OperationLog" ORDER BY created_at DESC LIMIT 5;
   ```
3. 确认返回非空记录后，再批量处理其他步骤。
4. 全部完成后，刷新 Admin 后台，确认"总操作数"和图表不再为 0。

---

**执行顺序**：Phase 1（搜索定位）→ Phase 2（选一个步骤注入并验证）→ Phase 3（按映射表批量注入所有步骤）→ Phase 4（补 catch 块）→ Phase 5（全量验证）。

**先选一个最简单的步骤（如创意扩散或框架搭建）做试点，验证 OperationLog 能写入后，再批量处理其余步骤。**
