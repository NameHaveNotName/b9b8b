## Kimi Code 执行提示词

**任务：生成软著申请材料 —— 源代码前 30 页**

---

### 编排方向

**整体顺序**：从项目级配置到核心业务逻辑，按模块依赖关系递进。

1. **项目骨架层**：`package.json`、数据库 schema、框架配置（Next.js/TS 配置）——体现技术栈和架构
2. **基础设施层**：Supabase 客户端/服务端初始化、认证辅助、积分系统、操作日志——体现数据与权限基础
3. **业务 API 层**：按工作流顺序排列——用户/项目 → 创意扩散 → 框架搭建 → 风格统一 → 人物设计 → 概念图 → 分镜设计 → 宣传片/视频 → 充值 → 管理后台——体现核心功能完整性
4. **前端与组件层**：根布局、仪表盘、管理后台页面、通用组件、核心 Hooks——体现界面与交互

**截断原则**：按上述顺序读取，自然凑满 30 页（1500 行）。若某文件跨页，在分页处自然截断，下页开头标注续接。若读完上述类别仍不足 30 页，继续补充 `lib/` 和 `components/` 下的其他核心文件。

**排除原则**：不纳入第三方依赖目录、构建产物、静态资源、环境变量文件、测试文件、lock 文件。

---

### 格式方向

- **纸张**：标准 A4，固定行距，确保每页恰好 50 行
- **页眉**：软件全称 + 版本号，居中
- **页脚**：连续页码（第 1 页至第 30 页），居中
- **代码字体**：等宽或宋体，小字号，保持原始缩进和换行，不人为插入空行凑页数
- **文件分隔**：不同文件切换时，加注释型分隔行（计入总行数）
- **跨页标记**：文件在页中截断时，当前页尾标注"续"，下页头标注"续 + 文件名"

---

### 安全方向

提取源代码前，全局扫描以下敏感信息并替换为占位符：
- 硬编码 API Key、Token、Secret
- 数据库连接字符串（含密码）
- 个人邮箱、手机号、身份证号
- 云服务真实 URL 或凭证

---

### 输出方向

- 生成标准 Word 文档（`.docx`）
- 保存到 `/mnt/agents/output/软著材料/` 目录
- 生成后报告实际纳入的文件清单和总行数
