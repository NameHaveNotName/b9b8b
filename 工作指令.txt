## Kimi Code 执行提示词

**任务：修复风格统一生图任务卡死问题 —— 后端错误传播 + 前端超时检测**

---

### Phase 1: 后端 — 生图 API 错误捕获与状态回传

**问题**：flux.1-kontext-pro 请求失败（图17），但任务状态未更新为 `failed`，前端永远读到 `processing`。

**修复逻辑**：

1. 打开风格统一步骤的生图 API（通常是 `app/api/style/generate/route.ts` 或类似路径）。
2. 找到调用外部生图 API（即梦/海螺/flux 等）的代码块。
3. **确保 `try-catch` 覆盖整个外部 API 调用链路**，包括：
   - 请求发送
   - 响应等待
   - 结果解析
4. **catch 块中必须执行**：
   ```ts
   // 1. 记录失败日志
   await logOperation({ ... status: 'failed', metadata: { error: error.message, model: selectedModel } });
   
   // 2. 更新任务/项目状态为失败
   await supabase.from('Project').update({ 
     styleStatus: 'failed',
     styleError: error.message 
   }).eq('id', projectId);
   
   // 3. 返回明确的错误响应给前端
   return NextResponse.json({ error: '生成失败', details: error.message }, { status: 500 });
   ```
5. **特别注意**：如果使用了队列系统（如 `generateQueue`），确保队列中的 `job` 在失败时标记为 `failed`，而不是永远 `active` 或 `processing`。

---

### Phase 2: 前端 — 轮询/长连接增加超时与错误检测

**问题**：前端显示"已 44690s"仍 90%，说明轮询逻辑没有识别后端错误。

**修复逻辑**：

1. 打开风格统一步骤的前端组件（`workflow/page.tsx` 或 `style-unify.tsx`）。
2. 找到轮询任务状态的 `useEffect` 或 `setInterval`。
3. **增加以下检测**：

```ts
// 在轮询逻辑中
const pollTask = async () => {
  const res = await fetch(`/api/project/${projectId}/status`);
  const data = await res.json();
  
  // 状态为成功或失败都停止轮询
  if (data.status === 'completed') {
    setGenerating(false);
    setProgress(100);
    return;
  }
  
  if (data.status === 'failed') {
    setGenerating(false);
    setError(data.error || '生成失败，请重试');
    return; // 停止轮询
  }
  
  // 超时检测：如果单个步骤超过 10 分钟（600s）仍在 processing
  const elapsed = Date.now() - startTime;
  if (elapsed > 600_000) {
    setGenerating(false);
    setError('生成超时，请检查网络或稍后重试');
    return; // 停止轮询
  }
  
  // 继续轮询
  setTimeout(pollTask, 3000);
};
```

4. **UI 层**：当检测到 `failed` 或 `timeout` 时：
   - 停止 loading/进度条动画
   - 显示错误提示（红色文字或 Alert 组件）
   - 提供"重试"按钮
   - 隐藏"中断"按钮或将其改为"清除错误"

### Phase 3: 生成队列 — 失败任务清理

**问题**：图16右下角"生成队列"显示"1 进行中"，说明队列中有死任务。

**修复逻辑**：

1. 打开生成队列相关组件（`GenerationQueue` 或 `TaskQueue`）。
2. 在队列状态同步逻辑中，增加对 `failed` 状态的识别：
   - 如果后端返回任务状态为 `failed`，将该任务从"进行中"移到"失败"列表，或标记为失败并允许用户删除/重试。
3. 增加队列级超时：
   - 如果某任务在队列中超过 15 分钟仍无进展，自动标记为超时失败。

**最优先**：Phase 1 + Phase 2，这两项解决"卡死"的核心问题。Phase 3 解决队列脏数据。
