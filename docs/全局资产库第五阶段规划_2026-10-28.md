# 第五阶段：个人资产库、项目资产与结构化设定

> 结论：个人库是“我的私有素材源”，项目资产是“团队共同使用的独立快照”。拖拽个人资产进入项目时，系统先复制快照，再建立使用关系；项目运行时绝不读取原个人资产。

## 1. 已确认的边界

- 项目侧边栏有两个页签：`项目素材`（项目成员可见）和 `我的资产库`（仅当前用户可见）。
- 从“我的资产库”拖入项目后，创建项目所有的独立资产；原作者以后修改或删除个人资产，不影响项目。
- 同一个人资产版本重复拖入同一项目，复用已有快照，不重复占用存储。
- 项目默认固定已复制的版本；个人库出现新版本时只提示，不静默升级。
- “上传、项目结果、资产库生成”是来源属性，不是三种资产类型。
- 回收站首期只覆盖个人资产和项目资产，保留 3 天；项目、视频工程等高风险对象另行设计。

当前实现尚未满足第一条隔离要求：`AssetBinding` 还能直接引用 `UserAsset`，且“复制到项目”沿用个人资产 URL。第五阶段必须改为真实对象快照与单向血缘记录。

## 2. 资产不是图片，而是带能力的内容对象

每个资产由五个相互独立的维度组成：

1. **内容类型**：图片、视频、音频、文本片段、角色卡、环境设定、故事模板、风格指南、道具/品牌设定。
2. **语义分类**：角色、场景、风格、道具、品牌、剧情、通用参考；同一资产可有多个语义标签。
3. **来源**：上传、项目生成结果、个人库生成、导入、人工创建。
4. **表现附件**：主图、补充参考图、视频、音色、文档等；结构化资产可同时带多种附件。
5. **版本与血缘**：当前版本、父版本、来源项目/任务、复制来源、内容哈希、生成配置快照。

建议的数据骨架：

```text
LibraryItem（个人私有逻辑资产）
  └─ LibraryRevision（不可变版本）
       ├─ StructuredPayload（按 schemaVersion 校验的角色/场景/模板数据）
       └─ Attachments（图片、视频、音频、文档）

ProjectAsset（项目独立快照，团队可见）
  ├─ lineage: sourceLibraryItemId/sourceRevisionId（仅追溯，不运行时依赖）
  ├─ payloadSnapshot + attachmentSnapshots
  └─ ProjectAssetBinding（绑定到步骤、角色、场景、镜头或参考槽）
```

结构化内容必须有版本化 JSON Schema；不能把任意自由文本直接拼进系统提示词。长文本只能作为“用户提供的创作约束”进入受限区段，并做长度、字段和权限校验。

## 3. 拖拽不是一个动作，而是“解释 + 预览 + 应用”

同一资产拖到不同位置，含义不同。系统先根据目标插槽选择适配器，再显示“本次会发生什么”，用户确认后才应用。

| 拖拽目标 | 默认解释 | 用户确认内容 | 保存范围 |
|---|---|---|---|
| 角色换图、分镜参考图槽 | 只取主图/所选附件 | 图片顺序、参考角色、权重 | 本次任务或项目绑定 |
| 创意扩散 | 注入软约束 | 角色性格、动机、世界设定中哪些启用 | 默认仅本次任务 |
| 框架搭建 | 创建或合并实体，并注入硬/软约束 | 新增/替换/合并；同名冲突；约束优先级 | 可选写入项目设定 |
| 角色设计、概念图、分镜设计 | 主图作视觉参考；选中的文字特征辅助提示词 | 实际发送的图片、文字、顺序 | 本次任务，确认后可固化 |
| 视频与尾帧 | 视觉附件为主；动作/连续性字段可选 | 起止帧、角色一致性、动作限制 | 本次任务 |

### 结构化资产的约束层

- `HARD`：不可违反的事实，例如“故事只能发生在月球基地”。
- `SOFT`：倾向，例如“角色经常在危难时救人”，允许剧情在合理时偏离。
- `REFERENCE_ONLY`：只取附件，不注入设定。
- 作用域分为 `THIS_RUN`、`THIS_STEP`、`PROJECT`；默认 `THIS_RUN`，避免一次拖拽永久污染项目。
- 合并策略只有 `ADD`、`REPLACE`、`MERGE_SELECTED_FIELDS`，禁止静默覆盖。

确认面板必须展示：将复制到项目的资产、将发送给模型的图片顺序、将加入的文字约束、会覆盖的已有字段、作用域以及预计点数。生成工作台的首次生成与重试共用这份快照。

## 4. 三条创建路径

### 上传图片

“新建资产”分为“上传媒体 / 创建设定 / 生成视觉资产”。上传采用渐进式表单：先拖文件并即时预览、校验格式与重复项，再只要求名称和语义分类；标签、描述和结构化信息可稍后补齐。多图可选择“多个独立资产”或“同一资产的多附件”。

### 保存项目生成结论

生成结果本来就是项目资产。用户点击或拖入“我的资产库”时，创建个人快照，并选择“新建个人资产”或“作为已有资产的新版本”。系统带出项目、步骤、模型、提示词、参考图和任务快照，但不会自动把项目资产变成个人资产。团队项目中的保存权限需记录原项目和创建者。

### 资产库独立生成

它对角色图、环境图、风格图等视觉资产有价值，复用“配置 / 执行”工作台，候选结果只有在用户挑选、命名后才成为版本。角色卡、环境设定、故事模板则使用结构化表单和 AI 辅助填写，不套用通用生图器；否则只会得到漂亮图片，得不到可控制的设定。

## 5. 回收站与定时清理

首期进入回收站的对象：`LibraryItem`、未被身份引用的孤立 `LibraryRevision`、未被有效绑定的 `ProjectAsset`。不进入用户回收站的对象：运行日志、生成任务记录、审计日志。项目和整部视频的删除另设“归档/删除项目”流程。

删除字段建议：`deletedAt`、`purgeAfter`、`deletedById`、`deleteReason`、`deletionBatchId`。回收站保存数据库墓碑和原存储键，不复制一份文件。

清理不由浏览器轮询，也不在普通请求中顺带执行：

1. Vercel Cron 或 Supabase `pg_cron` 每天低峰期运行一次。
2. 每次按游标分批处理 100～500 条，使用行锁/跳过锁定，保证幂等和可重试。
3. 先确认没有活跃引用，再删除 R2 对象，最后标记清理完成；失败进入重试队列。
4. `purgeAfter = deletedAt + 72h`。由于每日执行，实际物理删除会发生在 72～96 小时内。
5. 项目快照不因个人原件进入回收站而受影响。

## 6. 第五阶段实施顺序与验收门槛

1. **数据迁移**：落地 Prisma migration，停止运行时 `ensure*Table` DDL；建立个人版本、项目快照、附件、绑定和删除字段。
2. **权限边界**：个人库 API 只返回本人资产；项目 API 只返回项目快照；跨边界只能通过复制服务。
3. **创建与管理**：上传媒体、创建结构化设定、版本、搜索、标签、回收/恢复。
4. **双向拖拽**：个人库 → 项目快照 → 目标绑定；项目结果 → 个人库；完成重复检测和冲突预览。
5. **生成接入**：九步生成与重试统一读取“任务输入快照”，前端展示实际图片、文字、模型、画幅、阶段状态。
6. **独立生成**：视觉资产用生图工作台；结构化资产用表单 + AI 辅助；候选态不污染正式库。
7. **清理与审计**：3 天回收站、每日批处理、引用审计、权限与恢复测试。

关键验收：删除个人原件后项目仍能生成；项目成员看不到他人的个人库；拖入框架前能看见所有将新增/覆盖的设定；重试展示的输入与实际发送完全一致。

## 7. 明确不做的危险捷径

- 不允许项目绑定直接指向个人资产。
- 不允许结构化资产的自由文本未经分区直接注入系统提示词。
- 不允许拖入角色卡后静默改写整个项目。
- 不把“标签”当作结构化设定，也不把“来源”当作资产类型。
- 不让所有对象共用同一套级联删除规则。
- 不展示虚假的实时百分比，只展示供应商返回或系统真实可观测的阶段。
