## 2026-11-04 · Phase 1：生成单元、原始素材与剪辑时间线

### 数据结构

- 新增 `GenerationUnit`：表示一次供应商生成请求，可容纳单镜头或多镜头。
- 新增 `GenerationUnitItem`：表示长生成单元内部的创作镜头，并保留对旧 `VideoSegment` 的兼容映射。
- 新增 `GeneratedClip`：保存供应商返回的原始视频素材，与创作镜头解耦。
- 新增 `TimelineSegment`：保存素材入点、出点和成片时间线位置，为后续 1–2 秒拆镜提供 EDL 基础。
- 新增纯增量 Prisma 迁移；未执行线上数据库迁移，也未删除旧表或旧字段。

### 兼容接入

- 宣传片和直生视频在生成旧版 `VideoSegment` 后，尽力同步一份 2.0 生产计划。
- API 同时返回旧版 `segments` 和新版 `timeline`；数据库尚未迁移时自动回退，不影响 1.0 工作流。
- API 后台分支和 BullMQ Worker 都会把成功素材、模型、时长及失败状态同步到新结构。
- 重新生成计划时，只替换对应项目与步骤的 2.0 计划，不触碰旧版视频段和外部存储文件。

### 策略基础能力

- 新增相邻创作镜头打包器，可按场景边界、最长时长和最大镜头数构成长生成单元。
- 新增剪辑时间线构造器，明确区分素材源区间与最终成片区间。
- 新增成本比较器，计入模型最低计费时长、生成成功率和最终可用素材比例，而非只比较标称单价。
- 金额统一到六位小数，避免浮点误差进入策略判断或测试结果。

## 2026-11-04 · Phase 2C：时间线拆镜与失败回退

### 本轮实现

- 新增时间线导出计划器，按 `sourceStartMs/sourceEndMs` 从原始长素材精确提取每个创作镜头。
- 计划器校验素材时长、源区间越界、成片时间线连续性、源/成片时长一致性和重复 ID。
- 输出文件名经过安全清洗并固定加序号，避免镜头 ID 造成目录穿越或覆盖。
- 新增 `extractVideoRange` FFmpeg 路径，支持非零入点、精确时长、H.264 统一编码并尽力保留源音频。
- 导出任务顺序执行，避免在 Serverless 环境并行启动多个 FFmpeg 进程导致内存峰值。
- 新增长单元失败回退规划器：将 `MULTI_SHOT` 单元拆回逐镜 `SINGLE_SHOT` 请求，并重新计算模型、最低计费时长和费用。
- 新增数据库回退事务：保留失败长单元作为审计记录，新建逐镜计划，并把原时间线重新指向新单元；该函数只重排计划，不提交供应商任务。

### FFmpeg 稳定性修复

- 本地集成测试发现仓库中的 `ffmpeg-static` 文件存在但 Windows 无法启动，旧解析器会因只检查文件存在而直接失败。
- 解析器现在会逐个运行 `-version` 验证候选，跳过损坏二进制并继续寻找可用版本。
- Windows 本地增加已安装应用附带 FFmpeg 的低优先级兜底；生产环境仍优先使用明确的 `FFMPEG_PATH` 或构建产物。

## 2026-11-04 · Phase 2D：生成单元语义纠偏

### 用户确认的生产口径

- 一个生成单元可以在提示词内部包含多个短镜头，但供应商只返回一个完整视频。
- 完整视频直接作为最终时间线的一段，不按提示词时间码自动拆成多个文件。
- 内部镜头只承担叙事、切镜和参考素材编排职责，不是独立剪辑素材。
- FFmpeg 区间提取保留为人工修复工具，不进入正常自动装配路径。

### 参考项目证据

- “AI好创意广投”的 19 份分镜中，394 个可解析多镜头单元平均包含 3.51 个内部镜头：212 个为 3 镜头，167 个为 4 镜头，15 个为 5–6 镜头。
- 《角角当哥哥了》15 个真实任务为 6–15 秒，平均约 10.3 秒、3.6 个内部镜头；每个任务均返回一个 480P MP4。
- 因此 3–4 个内部镜头是常见值，不设置机械数量目标；连续动作允许单镜头，快切或蒙太奇可使用 5–6 个镜头。

### 本轮实现

- `TimelineSegment` 改为直接关联 `GenerationUnit`，删除对内部 `GenerationUnitItem` 和旧镜头的时间线依赖。
- 多镜头草案每个生成单元只创建一条时间线记录，元数据保留内部镜头 ID 与旧段映射，标记 `preserveWholeClip=true`。
- 供应商实际返回时长与计划不同时，完整保留视频并平移后续时间线，不再静默裁到计划时长。
- 多镜头失败降级为独立任务时，原单元时间线会被替换为逐镜单元，同时保留失败单元作为审计记录。
- 前端策略说明由“长生成单元后拆镜”改为“完整多镜头生成单元”。
- Seedance 2.0 时长按已确认的官方范围修正为 4–15 秒连续整数；Standard 默认改为 Seedance 2.0 Mini，Hero 保持 Seedance 2.5。此处曾写成“统一 480P”，现已更正：平台按各供应商最低成本原生档请求，不跨供应商统一分辨率。

### 成本边界（已由 Phase 2E 新证据替代）

- 本阶段按 Mini 计算出的约 `1.29s` 临界值，不适用于用户明确要求的低价 Budget 模型；不得继续用于产品决策。
- Budget 模型与真实成本边界以 Phase 2E 的 Vidu Q3 Turbo 核验结果为准。
- 实际推荐仍必须计入整单元失败的连带重试风险，不能只按秒价自动选择。

### 当前限制

- 多镜头付费执行开关仍关闭；本轮没有创建供应商任务或扣点。
- 数据库迁移在本阶段尚未部署；后续已于 Phase 2E 部署并完成数据核验。
- 自动装箱目前仍主要依赖顺序、时长、镜头数和场景分组；“一个主要戏剧任务”尚未形成结构化字段，是下一轮需解决的主要产品风险。

### 参考项目的多镜头口径

- 生成单元按“一个独立叙事职责”划分，而不是按固定镜头数划分；常见为 3–5 个内部镜头。
- 多个高难动作、场景/光线/核心角色或道具变化、时长不足、单阶段失败会连带报废整单元时，应拆成不同生成单元。
- 拆分点必须落在落地、站稳、动作完成等稳定状态，不拆开不可分割的发力或因果动作链。
- 复合参考素材按职责排序：角色身份、环境、起始状态、接触/动作关系、结束状态。每张图只对指定职责负责，并明确不继承的背景、文字或姿态。

### Budget 模型与成本纠偏

- Budget 默认模型改为 `viduq3-turbo`，Hero 保持 Seedance 2.5，Standard 保持 Seedance 2.0 Mini。
- 当前目录价按 Vidu Q3 Turbo `$0.0221/s`、最低 1 秒，与 Seedance 2.5 `$0.093/s` 比较，名义临界值约为 `0.237634s`。
- 因此对正常可用的极短镜头，Vidu 独立生成在名义价格上仍更便宜；把短镜头并入 Seedance 长单元的理由应是多参考一致性、复杂动作和质量，而不是省钱。
- Vidu Q3 当前已核验的最低成本原生档为 540P，因此请求 540P；Q2 按其目录使用 720P。任务原片不统一降到 480P，也不伪造供应商不支持的参数。

### 本轮实现

- Seedance 请求结构依据参考项目已成功任务纠正为 `ratio + resolution + duration + generate_audio + watermark`，全模态参考使用 `reference_image` 与 `omni_reference_task_type=reference`。
- 新增复合参考素材清单：按 URL 去重，同时保留素材职责、适用镜头、权威描述和排除项；多镜头提示词会生成稳定编号的参考图职责表。
- 多镜头草案现在可以为每个内部镜头绑定多张参考图，并按真实去重后的素材数执行模型上限检查。
- 建议前端采用“生成单元卡片 + 内部镜头时间线 + 可排序参考素材槽位”；每个槽位展示职责、适用镜头和排除项，避免只有一个含义不明的上传框。

### 审计修复与仍需处理的风险

- 已修复分镜参考图编号错位：同一 URL 跨类别重复时只上传一次，并把多个职责合并到同一个实际 Picture 编号。
- 上一镜头连续性目前依赖描述文本是否包含当前场景名，容易误判；应改用结构化场景/地点 ID 与显式连续性标记。
- 策略预览仍以幕/场景做粗分组，可能把不同戏剧任务装进同一生成单元；需要引入叙事职责和动作链边界。
- 前端目前只有只读预览，尚无“确认并开始生成”；草案转正式的交互与状态规则等待用户确认后实现。
