# 错误处理与日志规范 (Error Handling & Logging Standards)

## 错误码规范
格式：`{DOMAIN}_{3位序号}`

| 错误码 | 含义 | 用户提示 |
|:---|:---|:---|
| AUTH_001 | 未登录 | "请先登录" |
| AUTH_002 | 权限不足 | "无权访问该项目" |
| WORKFLOW_001 | 步骤不存在 | "工作流步骤未找到" |
| WORKFLOW_002 | 状态流转非法 | "当前步骤无法执行此操作" |
| API_001 | 上游 API 调用失败 | "生成服务繁忙，请稍后重试" |
| API_002 | API 密钥无效 | "服务配置异常，请联系管理员" |
| API_003 | 速率限制触发 | "操作过于频繁，请稍后再试" |
| QUEUE_001 | 任务入队失败 | "任务提交失败，请刷新重试" |
| QUEUE_002 | 任务超时 | "生成耗时过长，已自动取消" |
| MOD_001 | 内容审核未通过 | "输入内容包含敏感信息，请修改后重试" |
| STORAGE_001 | 文件上传失败 | "文件上传失败，请检查网络" |
| STORAGE_002 | 预签名 URL 过期 | "链接已过期，请重新获取" |

## 日志规范
每条日志必须包含：
```json
{
  "timestamp": "ISO8601",
  "level": "INFO|WARN|ERROR",
  "requestId": "uuid",        // 单次请求唯一ID
  "userId": "string|null",
  "action": "string",         // 如 GENERATE_VIDEO
  "errorCode": "string|null",
  "message": "string",
  "metadata": {}              // 额外上下文
}
```

## 用户体验规范
1. 技术错误绝不暴露原始堆栈给用户
2. 异步任务失败时，前端显示"生成失败，点击重试"，并将错误码上报
3. 内容审核拦截时，明确告知用户哪类违规（政治/色情/暴力/侵权）
4. 网络超时统一显示"连接超时，请检查网络或稍后重试"
